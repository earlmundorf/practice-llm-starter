THINK-142

Expose promotional pricing in the OCC v2 REST product payload

Type Story Priority Medium Components Backend · OCC API Repo sap-mcp-server-l

Description

As the storefront, when a product has an active promotion, I need the promo price present in the product data I fetch, so that the UI (THINK-143) can show the deal.

The storefront reads the OCC v2 REST API (/products/search, /products/{code}) — which carries only the base price today. Expose the promotion on the product node there.

Acceptance Criteria

  1. A promoted product returns a promo block on the product node in GET /products/{code} (OCC v2 REST).
  2. The same promo block appears in GET /products/search results.
  3. A product with no active promotion returns no promo block, unchanged otherwise.
  4. Values match the active promotion for the product on electronics.
  5. Parity, not a fork: reuse the existing PromoPricing DTO / promo service that already power the MCP tool responses.

Notes / Context

  • “OCC payload” = the OCC v2 REST responses the storefront reads (commercewebservices) — not just the MCP tools.
  • 142’s first pass added promo to the MCP handlers only; OCC REST still lacks it — this closes that gap.
  • Reuse PromoPricing/PromoNodeWriter; add a commercewebservices populator. Don’t modify OOTB.

Out of Scope

  • Creating or administering promotions.
  • Sale indicators outside grid + PDP.
  • The frontend rendering — that’s THINK-143 below.
THINK-143

Render sale price & “Sale” badge in the storefront (grid + PDP)

Type Story Components Storefront (React) Repo sap-mcp-ui-l (sibling) Depends on THINK-142

Description

As a shopper, when a product is on promotion, I want the grid card and detail page to show the sale price, struck original, and a “Sale” badge.

The frontend half of 142: extend mapOccProduct + the Product type, then render in ProductCard.tsx and ProductDetail.tsx. Shorter, UI-only.

Acceptance Criteria

  1. On the product grid, a promoted product shows the discounted price, the original price struck through, and a “Sale” badge.
  2. On the product detail page, the same discounted price, original price, and badge appear.
  3. A product with no active promotion is unchanged.
  4. The sale/original price matches the OCC payload from THINK-142.
  5. No regression to price display, stock indicator, or add-to-cart.
